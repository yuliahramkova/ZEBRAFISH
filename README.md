# NAOMi: распределённая генерация изображений zebrafish

Эта папка нужна для генерации **1000 независимых статических изображений** на нескольких компьютерах. Каждый запуск NAOMi создаёт один кадр **485 × 400 пикселей** и данные о сгенерированных клетках. Реальные TIFF-данные Zenodo в репозиторий не входят.

## Что лежит в папке и зачем

| Файл или папка | Назначение |
| --- | --- |
| `README.md` | Инструкция, в том числе распределение сидов между компьютерами. |
| `profile.json` | Зафиксированные параметры серии. Изменять их посреди серии нельзя: изображения перестанут относиться к одному датасету. |
| `density_prior_seed20262001.png` | Карта вероятности размещения клеток: где клетки встречаются чаще, а где реже. Это вход генератора, не готовый кадр. |
| `run_batch.py` | Главная команда: назначает номера и сиды, запускает Octave, сохраняет кадры и позволяет продолжить прерванный расчёт. |
| `simulator/code/run_naomi_density_image.m` | Один запуск модифицированного NAOMi: размещение клеток → оптика → шум → PNG, массивы и координаты клеток. |
| `simulator/code/VolumeCode/` | Размещение клеток и построение объёма с ядрами. |
| `simulator/code/OpticsCode/` | Модель света, рассеяния и размытия микроскопа. |
| `simulator/code/ScanningCode/` | Превращение светящегося объёма в кадр и добавление шума камеры. |
| `simulator/code/MiscCode/`, `ExternalPackages/` | Небольшие математические функции, которые вызывают три предыдущих этапа. |
| `simulator/code/TimeTraceCode/check_spike_opts.m` | Проверяет служебные параметры одного статического кадра; временные ряды здесь не генерируются. |
| `simulator/code/MEX/*.cpp` | Две ускоренные функции C++: точное размещение клеток и выборка из массива. Их нужно собрать на каждом компьютере. |
| `scripts/build_mex.py` | Собирает эти две функции под установленный Octave и процессор компьютера. |
| `scripts/smoke_test.py` | Генерирует пробный кадр с 20 клетками, чтобы проверить установку. |

| `.gitignore` | Не даёт случайно добавить в Git огромные результаты, логи и собранные бинарные файлы. |
| `LICENSE-NAOMi.md` | Условия использования исходного кода NAOMi. |

В `simulator/code` оставлены только функции, которые понадобились для **этого фиксированного режима**: 43 файла `.m` и два исходника `.cpp`. Функции исходного NAOMi для видео, деконволюции, дендритов, сосудов и анализа результатов удалены из копии, которую нужно загрузить в Git. Если позже захотим включить эти режимы, их придётся вернуть из исходного NAOMi.

## Что зафиксировано

Параметры записаны в [`profile.json`](profile.json): 12 000 клеток, радиус ядра 1,6 мкм, объём 350 × 423 × 10 мкм, excitation NA 0,6, objective NA 0,8, halo scale 0,75 и локальное свечение `+10`. Используется ядерный быстрый режим NAOMi, без сосудов, дендритов, движения и отдельно нарисованного контура. Положение клеток берётся из фиксированной карты плотности [`density_prior_seed20262001.png`](density_prior_seed20262001.png), построенной по [публичной записи zebrafish на Zenodo](https://zenodo.org/records/6293696/). Это эвристическая карта вероятности, а не экспертная разметка.

Это модифицированная версия [NAOMi](https://bitbucket.org/adamshch/naomi_sim/src/master/): ускоренное размещение клеток, быстрый ядерный объём и необязательное локальное свечение, вычисляемое из клеток перед моделью шума камеры. Условия исходного кода сохранены в [`LICENSE-NAOMi.md`](LICENSE-NAOMi.md). Для публикации результатов с использованием реальных данных укажите также источник Zenodo и работу DeepCAD-RT.

## Установка на каждом компьютере

Нужны Python **3.10+** без сторонних библиотек, GNU Octave с `mkoctfile` и C++-компилятором. Здесь проверено на Octave **11.3** для macOS. Пакеты Octave: `image`, `statistics`, `signal`; для текущей версии `statistics` также нужен `datatypes`. Если пакеты ещё не установлены:

```bash
octave --quiet --eval 'pkg install -forge datatypes'
octave --quiet --eval 'pkg install -forge image'
octave --quiet --eval 'pkg install -forge signal'
octave --quiet --eval 'pkg install -forge statistics'
```

После клонирования репозитория перейдите в **эту папку** и соберите два MEX-модуля под процессор и Octave данного компьютера:

```bash
cd naomi_zebrafish_distributed
python3 scripts/build_mex.py
python3 run_batch.py check
python3 scripts/smoke_test.py
```

Готовые `.mex` с нашего Mac намеренно не включены в репозиторий: на Linux/Windows/другом Mac они могут не работать. `smoke_test.py` создаёт маленький кадр с 20 клетками примерно за несколько секунд, прежде чем машина возьмётся за долгую серию. Если `check` сообщает об отсутствующем пакете Octave, установите его и повторите проверку. На Windows также понадобится доступный в `PATH` `mkoctfile` и настроенный для Octave C++-компилятор; этот вариант пока не проверен нами.

## Как не повторить сиды

У каждого изображения есть **глобальный номер** от `0` до `999`:

```text
seed = 20263000 + глобальный_номер
```

Каждому компьютеру назначьте **непересекающийся полуоткрытый диапазон** `[start, stop)`. Например, если всего три компьютера:

| Компьютер | Номера | Сиды | Команда |
| --- | --- | --- | --- |
| Юля, текущий Mac | `0–499` | `20263000–20263499` | Уже запущенная локальная серия; см. ниже |
| Второй | `500–749` | `20263500–20263749` | `python3 run_batch.py run --start 500 --stop 750 --workers 4` |
| Третий | `750–999` | `20263750–20263999` | `python3 run_batch.py run --start 750 --stop 1000 --workers 4` |

Если дополнительный компьютер только один, дайте ему диапазон `500–999` командой `python3 run_batch.py run --start 500 --stop 1000 --workers 4`. Если компьютеров больше, делите **только ещё не назначенные** номера. Число после `--stop` **не входит** в диапазон. Проверить план без генерации:

```bash
python3 run_batch.py plan --start 500 --stop 750
```

**Юля уже запустила на своём Mac генерацию первых 500 изображений**, номера `0–499` и сиды `20263000–20263499`. Расчёт продолжается; готовые изображения сохраняются по мере завершения. Не назначайте этот диапазон другому компьютеру. Один и тот же глобальный номер на двух машинах означал бы один и тот же сид; разные версии Octave при этом могут дать немного разные пиксели, поэтому сверять надо именно номера и сиды.

## Запуск и результат

Выбирайте `--workers` по возможностям машины. На нашем Mac с 14 логическими ядрами работают 8 процессов параллельно; для менее мощного компьютера начните с 2–4. Например:

```bash
python3 run_batch.py run --start 500 --stop 750 --workers 4
```

Файлы появляются **после завершения каждого отдельного кадра**. Папка по умолчанию: `outputs/shard_0500_0750/`. В ней:

- `images/` — готовые PNG с номером и сидом в имени;
- `manifest.csv` — соответствие номера, сида, PNG и контрольной суммы;
- `progress.json` — текущий счётчик;
- `runs/` — исходные массивы NAOMi, центры клеток и проекции ядер для последующей разметки;
- `logs/` — журнал каждого запуска Octave;
- `state/` — файлы для возобновления после остановки.

Проверить состояние или продолжить после остановки:

```bash
python3 run_batch.py status --start 500 --stop 750
python3 run_batch.py run --start 500 --stop 750 --workers 4
```

Повторная команда пропустит проверенные кадры. Выходные данные исключены из Git через `.gitignore`: **в репозиторий загружайте код**, а PNG передавайте вручную. Для обучения сегментации сохраните также `runs/`: файл `nucleus_footprints_native_u16.bin` хранит тройки `(id клетки, y, x)` на исходной сетке NAOMi 350 × 423, а PNG имеет размер 400 × 485. Это не готовая PNG-маска на конечной сетке.

## Как собрать PNG с разных компьютеров

На одном компьютере создайте папку `incoming/`. Каждый участник **вручную копирует туда готовые PNG** — можно раскладывать по подпапкам `incoming/yulia/`, `incoming/computer_2/` и так далее. Копировать большие папки `runs/` и служебные файлы `state/` для этого шага не нужно. PNG Юли сейчас лежат в `/Users/bubidla/Documents/Codex/2026-10-21/new-chat/work/naomi_batch_12000_localbg10/images/`; PNG новых компьютеров будут в их `outputs/shard_XXXX_YYYY/images/`.

Имена файлов сохраняйте исходные, например `naomi_0500_seed20263500.png`. После копирования выполните из папки проекта:

```bash
python3 collect_png.py
```

Скрипт найдёт все PNG в `incoming/` и создаст `dataset_png/images/` и `dataset_png/manifest.csv`. Он остановится, если встретит повтор номера, неверный сид, неверный размер 485 × 400 пикселей или неожиданный формат имени. Можно добавлять новые PNG в `incoming/` и повторять команду: уже собранные файлы она пропустит. Когда нужны строго все 1000 изображений:

```bash
python3 collect_png.py --require-complete
```

Это **сбор отдельных файлов в одну папку**, а не склейка кадров в одно изображение. `incoming/` и `dataset_png/` исключены из Git. Скрипт собирает только PNG: исходные массивы NAOMi и маски остаются в папках генерации и при необходимости передаются отдельно. При ручной передаче PNG невозможно автоматически доказать, что на всех компьютерах был одинаковый код и параметры; команда проверяет только имя, сид, размер и совпадение уже собранных файлов.
